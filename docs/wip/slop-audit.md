## High-priority cleanups

### 1. Codegen `flows.rs` generates flows that bypass the layer contract

**File:** `blast/src/codegen/flows.rs:152-178` — `verb_stub_body()`

The generated flow stubs call `crate::models` directly:
```
"use crate::models;\n"
...
"    let out = models::{table}::{model_call}(&mut conn{args_call}).await?;\n"
```

This violates LAYER:12 (flows must call routines, not models directly). Generated flows should delegate to `crate::routines::generated::<table>::<verb>` instead, mirroring how the hand-written canonical flows (`flows/auth/login.rs` etc.) call routines.

Additionally, the generated stubs have no `Crank` wrapper at all — no `Crank::none()`, no `Crank::backoff(...)`. The contract requires every flow to declare an explicit retry policy. Canonical hand-written flows all declare `Crank::none()` even when no retry is desired. Generated stubs silently break this invariant.

**Fix:** Codegen should emit:
1. `use crate::crank::Crank;` import
2. A `Crank::none()` (or `Crank::backoff(3, Duration::from_millis(200))` for reads) wrapping the routine call
3. Route the call through `routines::generated::<table>::<verb>` rather than `models::<table>::<verb>`

### 2. `error_handler.rs` — `rate_limit_error()` uses wrong `MeltType`

**File:** `templates/canonical/src/transport/http/middleware/error_handler.rs:128-132`

```rust
pub fn rate_limit_error() -> MeltDown {
    MeltDown::new(crate::meltdown::MeltType::BadRequest, "Rate limit exceeded")
        .with_user_message("Too many requests. Please try again later.")
        .with_context("error_type", "rate_limit")
}
```

This creates a `BadRequest` (400) instead of `TooManyRequests` (429). The canonical constructor for rate-limit errors is `MeltDown::too_many_requests(retry_after)` which correctly uses `MeltType::TooManyRequests` and wires up the `Retry-After` header. This slop function produces the wrong status code and silently discards `retry_after`.

**Fix:** Delete `rate_limit_error()` entirely — callers should use `MeltDown::too_many_requests(duration)` directly. If a duration isn't known at call site, document that.

### 3. Dead utility functions in `error_handler.rs` never called externally

**File:** `templates/canonical/src/transport/http/middleware/error_handler.rs:73-132`

Five public helper functions — `create_error_response`, `validation_error`, `auth_error`, `authz_error`, `not_found_error` — have zero callers anywhere in the codebase. They are wildcard-re-exported from `middleware::mod` (`pub use error_handler::*;`), so they pollute the public API surface of the middleware module.

`create_error_response` also imports `chrono::Utc::now().to_rfc3339()` which would add an implicit `chrono` dependency on downstream consumers, and it duplicates what `MeltDown::into_response()` already does correctly.

These functions were likely scaffolded by a cleanup wave as "useful utilities" but they conflict with the canonical pattern of using `MeltDown` constructors directly.

**Fix:** Delete all five functions. The `pub use error_handler::*;` glob in `middleware/mod.rs` should be replaced with explicit named imports of only what is actually used (`error_handling_middleware`, `panic_handler`).

### 7. `crank.rs` exposes `retry_only_transient()` which conflicts with policy

**File:** `templates/canonical/src/crank.rs:148-150`

```rust
pub fn retry_only_transient(self) -> Self {
    self.classify(|e: &MeltDown| e.is_transient())
}
```

This method is a foot-gun. The canonical classifiers for `Crank::backoff` and `Crank::fixed` use `!e.is_permanent()` (which includes errors that are neither explicitly permanent nor explicitly transient). `retry_only_transient()` is narrower — it only retries errors where `transient == true`, missing retry-eligible `ExternalServiceError` and `DatabaseConnection` cases where `default_transient()` didn't fire but `is_permanent()` is also false.

Additionally, `is_transient()` is the "old" API (checks the `transient: bool` field) while `!is_permanent()` is the newer, more complete check. Having `retry_only_transient()` on the public `Crank` API invites callers to use the weaker classifier.

**Fix:** Either remove `retry_only_transient()` or add a doc note that `Crank::backoff`/`Crank::fixed` already use `!is_permanent()` as default and that `retry_only_transient()` is a subset.

## Low-priority polish

### 8. `api_logger_middleware` and `error_handling_middleware` both log request/response

**Files:**
- `templates/canonical/src/transport/http/middleware/api_logger.rs` — logs `API Request` + `API Response` at Debug
- `templates/canonical/src/transport/http/middleware/error_handler.rs:15-52` — logs at Info/Warning/Error per status code range

Both middlewares are stacked in `main.rs` (lines 64-65). The `api_logger` fires at Debug level and the `error_handling_middleware` fires at Info+ — so in prod the API logger is silent but `error_handling_middleware` still logs everything. The `api_logger` middleware is effectively dead in any non-Debug log level and its output duplicates the tower trace span (from `trace::make_trace_layer()`). Three logging sources for a single request.

**Fix (low priority):** Evaluate whether `api_logger_middleware` should be removed in favour of the tower trace layer, or whether the debug/info split is intentional for development vs production.

### 9. `structs/auth/mod.rs` uses blanket `pub use *` re-exports

**File:** `templates/canonical/src/structs/auth/mod.rs:12-21`

All 10 auth struct submodules are re-exported with `pub use <mod>::*;`. This makes the full contents of all submodules visible without qualification, which can cause name collision surprises if generated resources add types with colliding names (e.g. a generated `User` that conflicts with the canonical `User`).

The `structs/mod.rs` then does another `pub use auth::*;` creating a second-layer glob. Callers have to mentally unroll two levels of glob to know where a type lives.

**Fix (low priority):** Replace the `*` re-exports with explicit named re-exports for the types that need to be in scope crate-wide. Types used only within `structs/auth/` don't need re-exporting at the top level.

### 10. `crank.rs` `retry_all()` has no caller and is a trap

**File:** `templates/canonical/src/crank.rs:152-154`

```rust
pub fn retry_all(self) -> Self {
    self.classify(|_: &MeltDown| true)
}
```

`retry_all()` will retry even on `ValidationFailed`, `Unauthorized`, `NotFound` — permanent failures that will never succeed. There is no caller anywhere in the codebase. This is dead API that will cause silent infinite-retry hammering if misused.

**Fix:** Remove `retry_all()` unless there is a documented use-case. If retained, add a panic or at least a log warning that it retries permanent errors.

## Notes / context

### Non-issues ruled out

- **Routines importing `crate::database`**: Checked all routine files. None import from `crate::database` directly. All DB access goes through `ctx.conn()` and models, which is correct.

- **Ad-hoc `Crank::new(policy)` in flows**: No flows use `Crank::new(...)` with raw policy construction. All canonical hand-written flows use `Crank::none()` correctly.

- **`is_transient()` in flow classifiers**: No flows have custom classifiers. The only `is_transient()` call in flows-relevant code is inside `crank.rs`'s own `retry_only_transient()` method (item 7 above).

- **`MeltDown` construction missing `retry_after` in transport**: The `parse_retry_after` helper exists in `services/external_http.rs` but there are no `ExternalServiceError` flows in the canonical templates — all flows are DB-backed. No 429/timeout context exists yet where `parse_retry_after` would apply. Not a gap in current code.

- **Codegen output paths**: All codegen emits to `<layer>/generated/` correctly — `src/flows/generated/`, `src/transport/http/generated/`, `src/structs/generated/`. The two-tier model is respected in output paths.

- **Stale `custom/` references in canonical `templates/` Rust code**: Zero hits. The `custom/` references are confined to blast's own codegen doc comments and governor rule logic (items 5 and 6 above).

- **`pub use` re-exports in flows**: The `pub use crate::structs::auth::{LoginInput, LoginOutput};` in `flows/auth/login.rs` is a legitimate convenience re-export to avoid callers having to reach into structs. Acceptable pattern.

- **`structs/fuses/table.rs` re-exporting from `crate::database::schema`**: This is the documented `structs` exception for schema access (`STRUCTS:22` exempt path). Confirmed clean.
