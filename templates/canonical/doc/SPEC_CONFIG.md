# SPEC_CONFIG

Zero-TOML config topology. Everything user-editable is RON state files (owned by Blast) or `.env`.

## File Layout (user's app)

```
my-catablast-app/
├── Cargo.toml                  (main app)
├── build.rs                    (stale-codegen guard — fails if state hash ≠ generated header)
├── .env                        (runtime values + secrets, gitignored)
├── .env.example                (template, auto-generated by Blast)
├── .gitignore                  (ignores .env, target/, node_modules/)
├── src/                        (app code)
│   ├── main.rs
│   ├── bootstrap.rs
│   ├── structs/{generated,custom}/
│   ├── database/
│   ├── models/{generated,custom}/
│   ├── services/
│   ├── routines/{act,collect,derive}/
│   ├── flows/{generated,custom}/
│   └── transport/{http,ws,fuses}/{generated,custom}/
├── migrations/                 (Diesel migration SQL files)
├── storage/
│   └── blast/
│       └── state/
│           ├── app.ron             (app-level config: project name, env vars, fe_lint, admin actions)
│           └── resources/
│               ├── users.ron       (per-resource: fields, variants, flows, WS, admin hints)
│               └── orders.ron
└── frontend/
    ├── package.json
    ├── vite.config.ts
    ├── src/
    │   ├── generated/{types,api,composables}/
    │   ├── styles/{tokens.css,base.css}
    │   ├── plugins/primevue.ts
    │   └── (hand-written Vue code)
    └── scripts/governor-plugin.js  (Vite plugin, calls `blast check`)
```

## State File Format: RON

All Blast state files use [RON](https://github.com/ron-rs/ron) (Rusty Object Notation).

- Serde-derive compatible: Blast parses to typed Rust structs.
- Line-diffable: one field per line; `git diff` is readable.
- No invisible whitespace sensitivity.
- Each file carries `schema_version: N`; Blast auto-upgrades old files on load.

RON files live under `storage/blast/state/`. The `storage/` directory is for runtime + tooling artifacts; the `blast/state/` subtree is Blast's exclusive territory.

## State File Ownership

| File | Mutated by | Read by |
|------|-----------|---------|
| `storage/blast/state/app.ron` | Blast TUI (`blast gen app`) | Blast codegen |
| `storage/blast/state/resources/<name>.ron` | Blast TUI (`blast gen resource`) | Blast codegen |
| `src/<layer>/generated/` | `blast gen all` | Rust compiler |
| `.env` | Developer/ops (hand-edit or `blast env set`) | Runtime app |
| `.env.example` | `blast gen all` | Developers |

## Sources of Truth

| Concern | Where |
|---------|-------|
| Per-resource shape/flows/WS/admin hints | `storage/blast/state/resources/<name>.ron` |
| Project name | `storage/blast/state/app.ron` |
| Env var spec | `storage/blast/state/app.ron` |
| Global default struct derives | `storage/blast/state/app.ron` |
| FE lint rules | `storage/blast/state/app.ron` |
| Admin actions | `storage/blast/state/app.ron` |
| Runtime values / secrets | `.env` |
| DB schema (physical truth) | `src/database/schema.rs` (regenerated from migrations) |
| Rust deps | `Cargo.toml` (tool-imposed) |
| Frontend deps | `frontend/package.json` (tool-imposed) |

No `Catalyst.toml`. No alternative config file. No overlap.

## Workflow: Explicit Two-Step

State mutation and code generation are intentionally separate steps:

1. **TUI mutates state** — `blast gen resource orders` opens the dialoguer wizard, writes `storage/blast/state/resources/orders.ron`.
2. **Codegen regenerates** — `blast gen all` reads all RON files + `schema.rs`, stomps `src/<layer>/generated/`, emits FE types.

Never automatic. Always explicit. The user sees exactly what changed (state diff), then explicitly re-generates.

Power users may edit `.ron` files directly. Blast re-reads on next `blast gen all`.

## Stale Codegen Guard

Every generated file header carries the SHA-256 hash of the source state file:

```rust
// GENERATED BY BLAST — source: storage/blast/state/resources/users.ron
// state_hash: a3f8c2...
// Do not edit. Run `blast gen all` to regenerate.
```

`build.rs` verifies: for each generated file, re-hashes the corresponding state file and fails the build if the hash mismatches. Result: `cargo build` hard-fails with a clear message if the user edited a state file but forgot to run `blast gen all`.

## `.env` Role

Anything the RUNTIME app reads: `.env`. Anything CODEGEN reads: RON state files. No mixing.

```bash
# .env (example)
DATABASE_URL=postgres://catablast:hunter2@localhost/catablast_dev
SESSION_SIGNING_KEY=<32+ random bytes>
STRIPE_API_KEY=sk_test_abc123...

PORT=8000
LOG_LEVEL=debug
MAINTENANCE_MODE=false
RATE_LIMIT_PER_MIN=60

PUBLIC_BASE_URL=http://localhost:8000
```

Flip a value, restart the binary, done. No rebuild.

## `.env.example` Auto-Generation

Blast reads the env var spec from `app.ron`, emits:

```bash
# .env.example
# Required
DATABASE_URL=postgres://user:pass@host/db
SESSION_SIGNING_KEY=<generate with: openssl rand -hex 32>

# Optional (defaults shown)
PORT=8000
LOG_LEVEL=info  # trace|debug|info|warn|error
MAINTENANCE_MODE=false
RATE_LIMIT_PER_MIN=60
```

Template is always in sync with the state spec. Never hand-maintained.

## Custom Escape Hatch

Anything the TUI cannot express goes in `src/<layer>/custom/`. No `raw_rust` field in RON state — that would leak the DSL problem into the state files. If you need behavior beyond what the state model supports, hand-write it in `custom/`, wire it in the layer's `mod.rs`.

Blast never touches `custom/`.

## Path Conventions (Not Configurable)

Blast bakes paths into itself. No config for:

- `migrations/` directory location
- `src/database/schema.rs` generated file location
- `src/structs/generated/`, `src/models/generated/`, `src/flows/generated/` output dirs
- `storage/blast/state/` state file root
- `frontend/src/generated/` output dir

If a user needs a non-standard layout, they fork Blast.

## What's Deleted / Not Used

Not present in Catablast's model:
- `catalyst_primer` sub-crate — dead. State lives in `storage/blast/state/resources/`.
- `catalyst_blueprint` sub-crate — dead. State lives in `storage/blast/state/app.ron`.
- `target/primer/*.json` IR files — dead. RON files are the IR.
- `target/blueprint/*.json` IR files — dead.
- `Catalyst.toml` — removed, dead concept
- `[codegen.hooks]` — hooks in generated code are banned
- `[assets.htmx]` — HTMX killed from stack
- `[required_env] JWT_SECRET` — JWT killed, sessions use `SESSION_SIGNING_KEY`
- Path configuration — baked convention

## Daily Workflows

**Flip a runtime setting** (log level, maintenance mode):
```
vim .env
# save, restart binary
```

**Change app-level config** (new env var, new lint rule, new default derive):
```
blast gen app     # TUI; updates storage/blast/state/app.ron
blast gen all     # re-emits generated code, .env.example, Governor config
cargo build
```

**Add or modify a resource:**
```
blast gen resource orders     # TUI; writes storage/blast/state/resources/orders.ron
blast gen all                 # regenerates all derived code
cargo build
```

**Nuke from orbit:**
```
blast gen all     # regenerates everything from state files + schema.rs
```
